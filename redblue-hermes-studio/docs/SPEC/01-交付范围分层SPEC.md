# 01-交付范围分层 SPEC

## 1. 分层原则

| 层级 | 定义 |
| --- | --- |
| 核心必交付 | 期内必须完成，缺失导致 Demo 不成立 |
| 增强交付 | 期内尽量完成，显著提升完整度 |
| 冲刺交付 | 有余力时补齐 |
| 明确不做 | 本期不做，避免失控 |

## 2. 核心必交付

| 功能 | 为什么核心 | Owner | 降级 |
| --- | --- | --- | --- |
| 安全运营工作台入口 | 红蓝平台的门面 | A | 只做态势 + 任务两 Tab |
| 授权任务创建 | 红队执行的前提 | A/B | 必须含授权标记校验，不可降级 |
| 授权边界拦截 | 安全硬约束 | A | 不可降级 |
| 红蓝智能体定义（11 个） | 平台核心 | C | 先保红队指挥官 + 蓝队指挥官主链路 |
| 智能体编排画布 | 多智能体编排价值 | A/C | 只读展示编排 |
| 编排同步工作流 | 复用底座能力 | B/C | 仅本地同步 |
| 攻击链分析 | 证据驱动价值 | D | 仅展示真实消息 / 工具记录 |
| 事件报告导出 | 交付物价值 | D | 仅汇总文本 |
| 专属问答通道 | 任务内实时问答 | B | 复用普通聊天 |

## 3. 增强交付

| 功能 | 价值 | 降级 |
| --- | --- | --- |
| 态势总览实时指标 | 运营可视 | 静态汇总 |
| 技能使用统计 | 可观测 | 无 |
| CTF Skills 深度编排 | 能力扩展 | 单技能 |
| 事件报告 JSON 结构化 | 可复用 | 纯文本 |

## 4. 冲刺交付

| 功能 | 说明 |
| --- | --- |
| 攻击链可视化图 | 用表格 / 列表替代 |
| 报告多格式导出 | 本期 JSON 即可 |
| 蓝队处置建议自动化 | 本期人工确认 |

## 5. 明确不做

| 功能 | 原因 |
| --- | --- |
| 未授权安全测试执行 | 硬约束 |
| 独立后端扫描引擎 | 复用 Hermes 能力 |
| 生产变更自动执行 | 处置建议仅建议，需人工审批 |
| 新 UI 组件库 | 沿用 Naive UI |

## 6. Demo 必须保留的闭环

1. 启动 `dev:redblue` → 打开态势总览。
2. 创建授权任务（含 `AUTHORIZED_SECURITY_TEST`）。
3. 任务内问答（红蓝智能体参与）。
4. 展示智能体编排（11 智能体 + 连线）。
5. 攻击链分析基于真实会话 / 工具记录生成。
6. 导出事件报告 JSON。

若时间紧，优先保「授权任务 + 授权拦截 + 红蓝主链路智能体 + 攻击链 + 报告导出」。
