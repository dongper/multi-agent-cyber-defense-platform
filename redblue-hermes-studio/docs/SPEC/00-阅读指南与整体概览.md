# 00-阅读指南与整体概览

## 1. 本版本定位

这是「红蓝协同智能安全运营平台」的 **Hermes Studio 红蓝定制版 SPEC**，即 `redblue-hermes-studio`（`hermes-web-ui` v0.6.47 的红蓝分支）。

目标形态：一个内建授权边界、红蓝协同的多智能体安全运营工作台。它在 Hermes Studio 底座上新增 `/security-operations` 工作台，用 11 个红蓝智能体覆盖「授权任务 → 攻击验证 → 研判溯源 → 攻击链分析 → 事件报告」全链路。

```text
红蓝协同智能安全运营平台
├── Hermes Studio 底座（client / server / desktop）
└── 安全运营工作台（cyber-defense 模块）
    ├── CyberDefenseView（5 Tab）
    ├── CyberTaskWorkspace（授权任务 + 问答）
    ├── CyberAgentStudio（智能体编排）
    └── cyber-studio.ts（11 红蓝智能体定义）
```

## 3. 一句话定位

红蓝协同智能安全运营平台是一个内建授权边界的安全运营工作台，通过 11 个红蓝智能体的编排协作，完成授权安全任务、攻击链分析与事件报告，并坚持「证据优先、不推测补链」。

## 4. 本期核心目标

```text
授权任务（AUTHORIZED_SECURITY_TEST）
  → 红队攻击验证 → 证据校验
  → 蓝队研判 / 日志关联 / 恶意样本 / 攻击路径还原
  → 攻击链分析（真实会话 + 工具记录）
  → 事件报告（证据引用）→ 导出 JSON
```

## 5. 用户角色与核心场景

| 角色 | 想看什么 | 业务价值 |
| --- | --- | --- |
| 红队操作员 | 授权任务、攻击验证、证据校验 | 可控的授权安全验证 |
| 蓝队分析师 | 告警研判、日志关联、攻击路径还原 | 事件溯源与研判 |
| 安全运营负责人 | 态势总览、事件报告、处置建议 | 统筹红蓝协同与授权边界 |

## 7. 技术栈

同 Hermes Studio（Vue 3 / TypeScript / Koa / SQLite / Electron / Python），红蓝工作台基于 Naive UI + Vue Flow。

## 8. 最小成功标准

1. `npm run dev:redblue` 可启动并打开 `/security-operations`。
2. 任务中心可创建授权任务；无 `AUTHORIZED_SECURITY_TEST` 时执行被阻止。
3. 智能体编排可拖拽连线 11 个红蓝智能体并同步工作流。
4. 攻击链分析只基于真实会话 / 工具记录，空白任务不推断。
5. 事件报告可汇总并导出 JSON。

## 9. Demo 成功线

5 分钟内跑通：启动 → 打开态势总览 → 创建授权任务 → 问答 → 展示智能体编排 → 展示攻击链（真实会话）→ 导出事件报告。

## 10. 本期不要做

1. 不执行未经授权的安全测试（硬约束）。
2. 不新增后端安全扫描引擎（复用 Hermes 能力）。
3. 不自动执行生产变更（处置建议默认仅建议）。
4. 不新增 UI 库。
5. 不让前端接触模型凭证 / Token / Key。
