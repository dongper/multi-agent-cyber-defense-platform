# 中国联通专利交底书

## 核心原则

- 保持“现有技术缺点 → 技术问题 → 技术手段 → 技术效果 → 关键保护点”逐项对应。
- 只将来源材料或用户确认的信息写成确定事实。缺少实现细节时列出待补充项，不编造参数、数据、模块或效果。
- 公开检索可使用百度系或 Google 系入口；检索入口可以替换，但文献事实必须在专利详情页、官方数据库、出版商、DOI、arXiv 或论文全文等一手页面核验。不得仅凭搜索摘要或记忆撰写结论。
- 在技术方案需要数学表达时加入适当公式，并逐一定义符号、取值或维度、计算步骤和技术作用。不得加入与实现无关的装饰性公式。
- 使用中国专利文本风格，优先描述可执行的技术步骤、数据流、输入输出、约束关系和模块交互，避免宣传性语言。

## 开始前

1. 读取用户提供的论文、技术方案、项目材料、已有交底书及附图。
   - 用户说“第一个文件”时，按文件名自然排序，排除隐藏文件、临时文件和本任务输出文件；在开始撰写时明确所选源文件。
2. 用户要求生成或修改 DOCX 时，同时使用文档处理 Skill，并以 `assets/中国联通发明实用新型技术交底书模板.docx` 为版式基准。
3. 阅读 `references/unicom-disclosure-structure.md`，按联通交底书栏目组织内容。
4. 需要检索或撰写检索报告时，完整阅读 `references/prior-art-search.md`。
5. 需要补充技术方案或公式时，完整阅读 `references/formula-guidelines.md`。
6. 源材料为成果报告、五小申报、项目总结等非专利文档时，阅读 `references/source-type-project-report.md` 了解转化方法。
6. 交付前阅读 `references/review-checklist.md` 并逐项检查。

## 工作流

### 1. 建立发明事实表

提取并区分：

- 已明确事实：来源材料直接记载的结构、流程、算法、参数、数据和效果。
- 可合理改写内容：不改变技术含义的专利化表述。
- 信息缺口：无法从材料确定、会影响实施或保护范围的内容。
- 待用户确认内容：公开状态、落地系统、量化效果、替代方案和内部检索结果。

信息不足时先完成可完成的部分，并以简短问题集中追问关键缺口。

### 2. 检索现有技术

依据 `references/prior-art-search.md` 执行：

1. 从发明名称、技术问题、核心手段、关键数据结构和技术效果生成中文与英文检索式。
2. 根据可访问性选择百度/百度学术、Google/Google Scholar，以及 Google Patents、国家知识产权局、WIPO、Espacenet 等专利入口；用户指定入口时优先服从。
3. 对搜索结果进行一手来源核验，筛选最接近的专利与论文，核验编号、标题、日期、申请人或作者、摘要、核心技术手段及稳定链接。
4. 按技术问题、技术手段、技术效果和区别技术特征进行对比。
5. 将检索日期、检索式和来源链接写入工作底稿；不得伪造检索结果。

若某入口无法访问，可改用另一公开入口继续检索，并如实记录实际使用的入口。未能核验的编号或技术内容不得写成确定事实。

### 3. 撰写技术方案

- 给出至少一个完整、可实施的方案，明确输入、预处理、中间数据、处理步骤、判定规则、输出和异常分支。
- 对每一步回答：做什么、输入是什么、如何处理、输出是什么、与前后步骤如何衔接、解决什么技术问题。
- 对模型、算法或融合机制，写明训练阶段与推理阶段，避免将两者混写。
- 对阈值、评分、特征融合、损失函数、归一化、相似度、资源分配或风险计算，按 `references/formula-guidelines.md` 判断是否需要公式。
- 每个公式后立即解释全部符号、取值范围或维度、计算过程和对应技术效果。
- 公式必须与文字步骤及附图（如有）使用相同术语。
- 附图不是强制项。用户要求不附图或文字已经足以公开技术方案时，使用连续编号步骤完整写明模块、输入、处理、输出、顺序、分支和异常情况，并清除“如图所示”、图号、图题及附图依赖。

### 4. 提炼保护点与替代方案

- 保护解决技术问题所必需的技术特征组合，不把常规组件本身误写成创新点。
- 将核心流程、关键数据结构、模型协同关系、融合机制、阈值策略和可追溯输出分别评估为保护候选。
- 为模型类型、特征来源、编码方式、融合方式、阈值方式、部署位置和输出形式设计可实施替代方案。
- 替代方案不得超出来源材料能够支持或用户确认的范围。

### 5. 填写交底书与检索报告

按照模板原有顺序填入内容，尽量保持表格结构和固定栏目。公开检索报告必须写明实际使用的百度或 Google 等入口、检索日期、检索式、核验来源及对比结论；不得把普通网页搜索结果冒充专利或论文原文。中国联通内部专利数据库结果仅在用户提供访问或导出材料后填写，否则明确标记为待补充。

### 6. 质量检查

使用 `references/review-checklist.md` 检查：完整性、可实施性、对应关系、检索证据、公式、附图、保护范围、替代方案、术语一致性和格式。

## 输出要求

- 用户仅要求评审时，输出问题、影响和修改建议，不改原文件。
- 用户要求草稿时，先给结构完整的正文；对信息缺口使用清晰占位符。
- 用户要求最终 DOCX 时，填写模板、渲染全部页面并完成视觉检查后再交付；重点排查空白页、孤行、表格整行跳页、截断、重叠和无附图版本中的图号残留。
- 检索结论附近附可核验链接；区分来源原文、事实性概括和基于对比作出的推断。
