# 联通智能体 — 开发需求文档

> 版本：v1.0 ｜ 对应代码：`hermes-web-ui` v0.6.47（联通定制版） ｜ 周期：2026-08-24 → 2026-09-01

## 1. 背景与目标

### 1.1 背景

联通智能体是面向 Hermes Agent 的多智能体 AI 平台，采用「桌面应用 + Web 控制台 + 本地运行时」的分发形态，并在其基础上扩展了 Ekko 智能体运行时与 ESP32-C3 智能语音硬件，以覆盖「对话、工作流、模型管理、网页浏览、Coding Agent、语音交互、硬件接入」的完整链路。

### 1.2 目标

1. **多智能体协同**：Hermes Agent、Ekko Agent、Coding Agents（Codex / Claude Code / OpenCode）与群聊智能体在同一平台内编排协作。
2. **本地优先、可自托管**：本地运行时 + 自建 SQLite 会话库；模型凭证、Token 仅存本机，前端不直接接触密钥。
3. **全链路编排**：可视化工作流、定时任务、Kanban、平台渠道围绕同一套 Profile 配置运行。
4. **智能硬件接入**：ESP32-C3 语音设备完成 Wi-Fi 配网、语音交互、远程中继与 OTA 升级。

## 2. 用户角色

| 角色 | 核心诉求 |
| --- | --- |
| 终端用户 | 通过聊天与 Agent 交互、查看工具调用轨迹、生成文件预览、多会话管理 |
| 开发者 / 管理员 | 管理 Profile、Provider、模型、凭证、记忆、技能、插件、日志与运行时 |
| 运维 / 编排者 | 构建可视化工作流、配置平台渠道、Cron 任务、Kanban、群聊房间、MCP Server |
| 硬件使用者 | 通过 ESP32-C3 语音设备进行语音对话、配网与设备管理 |

## 3. 功能需求

### 3.1 AI 聊天（核心）

- Socket.IO `/chat-run` 实时流式更新，经 Hermes agent bridge 执行。
- 多会话管理（创建 / 重命名 / 删除 / 切换），本地 SQLite 会话库；Hermes state.db 仅作只读历史源。
- 按来源分组会话（Telegram、Discord、Slack 等）；活跃会话实时指示器；按最新消息时间排序。
- Markdown 渲染（语法高亮、代码复制）；工具调用详情展开（参数 / 结果）。
- 按 Profile 隔离的文件上传、剪贴板图片 / 文件粘贴与工作区附件。

### 3.2 群聊（多智能体协作）

- 群聊房间、多智能体提及路由、结构化提及协议、会话工作区 diff、房间成员管理。

### 3.3 可视化工作流

- 基于 Vue Flow 的节点化工作流编排；节点审批、结构化 JSON 条件、执行身份、生命周期恢复与可移植性。

### 3.4 平台渠道

- 社交消息接入：Telegram、Discord、Slack、飞书、微信等；消息绑定与运行时。

### 3.5 模型与配置管理

- 模型管理、Provider 管理、多 Profile 配置、运行时版本选择、凭证安全存储。

### 3.6 Coding Agents

- Codex / Claude Code / OpenCode 编码代理接入（代理路由），工具事件、推理上下文、API 模式。

### 3.7 桌面 Agent 浏览器

- 内置浏览器驱动 Agent 进行网页浏览与操作。

### 3.8 技能与记忆

- 技能管理（skill-bundles）、记忆读写、插件管理。

### 3.9 语音 / TTS / STT

- TTS 合成、STT 转写、实时语音对话、VAD 语音采集、多语音提供商（edge / openai / minimax / xai 等）。

### 3.10 Web 终端

- 基于 xterm.js 的终端；终端工作目录、命令执行。

### 3.11 智能硬件（ESP32-C3）

- v1 固件：Wi-Fi 配网、OLED 状态 UI、Hermes Web UI / 桌面发现、MCU 语音交互、远程中继、OTA。
- v2 固件：16MB 硬件修订，独立 `main.cpp`，音频调优（ES8311 DAC、音量增益与软限幅）。
- 服务端：设备发现、配对码、MCU 设备管理、固件下发。

### 3.12 其他

- 定时任务（Cron）、Kanban、用量分析、文件浏览器、主题自定义、日志、认证、设置、自动更新、性能监控。

## 4. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 性能 | 聊天流式响应；AI 调用超时不阻塞页面；前端首屏分包（bundle splitting） |
| 安全 | 凭证 / Token / AI Key 仅存后端；登录限流（login-limiter）；密钥日志脱敏；写入门禁（write-gate） |
| 数据 | 本地 SQLite 持久化；Web UI 状态与 Hermes 状态分离；支持 OTA 升级 |
| 兼容性 | Windows / macOS / Linux 桌面、npm CLI、Docker；Node ≥ 23 |
| 可维护性 | TypeScript 全量类型、Vitest + Playwright 覆盖、OpenAPI 契约生成 |
| 可扩展性 | monorepo 包边界清晰；Provider / 技能 / 插件可插拔 |

## 5. 核心业务流程

```text
用户输入（文本 / 语音 / 图片）
  → 客户端（Vue）→ Koa 后端 → Hermes / Ekko Agent 运行时
  → 工具调用（浏览器 / 终端 / 文件 / 设备 / Coding Agent）
  → 结果流式回传 → 前端渲染（Markdown / 文件预览 / 语音）
  → 会话与用量落库（SQLite）
```

硬件链路：

```text
ESP32-C3 语音设备 → Wi-Fi 配网 → 发现并配对（配对码）
  → 语音上行（ADPCM）→ STT → Agent 处理 → TTS → 设备播放
```

## 6. 验收标准（概览）

详细验收见 `docs/SPEC/07-验收标准与风险降级SPEC.md`，最小成功基线：

1. 桌面 / Web 端可启动并打开控制台。
2. 聊天可流式对话、工具调用轨迹可见、会话可持久化。
3. 工作流可编排并执行；定时任务 / Kanban 可用。
4. 模型 / Provider / Profile 可配置，凭证安全存储。
5. 至少一个平台渠道可绑定收发消息。
6. TTS / STT 可用；ESP32-C3 设备可配网、语音交互、OTA。
7. 重启后会话与配置仍在。
